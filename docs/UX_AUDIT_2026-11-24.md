## High-priority UX findings

### P0 — Asset selection will not scale to a global options universe

Evidence: App.tsx currently uses a single selected underlying state and a static UNDERLYING_NAMES dictionary. The top selector renders a horizontal set of underlying buttons. CSS fixes their width, and the data model has only a free-form underlying string; it has no first-class asset class or venue field.

Impact: Adding hundreds of underlyings across equities, indices, rates, FX, energy and agriculture would create a long, ambiguous chip strip. Users cannot first choose a market family, then a venue, then an underlying.

Change:
- Add a first-class asset-class taxonomy.
- Use a cascading filter: Asset Class → Venue → Underlying → Expiry.
- Keep a global symbol search and a watchlist/favourites list.
- Show result counts and a clear empty state when a venue has no instruments in the selected asset class.
- Derive available choices from loaded instruments, not a hardcoded list.

### P0 — Contract specifications are not rich enough for cross-market pricing

Evidence: OptionQuote has underlying, expiry, strike, call/put, unit, quoteAsset and basic fee fields, but no normalized exercise style, settlement style/asset, venue/legal entity, contract multiplier semantics, underlying kind (spot/future/index), or margin model.

Impact: A single Black–Scholes assumption can misprice or misstate risk for futures options, equity options with dividends, FX options, and commodity options. Two contracts with identical strike/expiry labels may have different multipliers, settlement and exercise mechanics.

Change:
- Create a canonical instrument-spec object with asset class, venue/legal entity, underlying type, quote/settlement currency, contract multiplier, tick/lot sizes, exercise style, settlement style, expiry timezone, fees and margin model.
- Preserve source values and normalization provenance.
- Use model routing: Black–Scholes with carry where appropriate, Black-76 for futures options, and a model explicitly selected for each product; never silently apply one model to all assets.
- Display a compact contract-spec panel beside the selected contract.

### P1 — Dense tables require too much horizontal scrolling on phones

Evidence: chain table min-width is 680px; journal table 750px; Greeks table 780px. The page requests a mobile viewport, but these tables necessarily overflow their containers.

Change:
- On mobile, render a compact option-chain row/card with Strike, Bid/Ask, IV and Delta; move OI/volume and secondary fields into an expandable detail panel.
- Keep desktop tables for dense comparison.
- Use a dedicated contract-detail drawer/bottom sheet on mobile rather than forcing a 780px Greeks table.
- Ensure touch targets are at least 44 CSS px and keyboard focus remains visible.

### P1 — Market freshness is not equivalent to streaming freshness

Evidence: Binance data is fetched as a REST snapshot and the UI tracks local receive age. A 60-second local threshold does not establish upstream timestamp freshness for every field.

Change:
- Show separate source timestamp and received-at timestamp per provider/field where available.
- Use clear labels: Live stream, REST snapshot, Historical, Imported CSV, Demo.
- Show quote age and stale status per selected contract.
- Never show a green “live” status solely because the local fetch happened recently.

### P1 — Venue comparison and market quality are not yet first-class

Evidence: the UI displays one data mode and a selected underlying. It does not yet show same-contract cross-venue quote comparison, depth-adjusted execution cost, or provider health.

Change:
- Add venue comparison only for genuinely equivalent contract definitions.
- Compare executable bid/ask, depth at intended notional, spread, fees, slippage and timestamp alignment.
- Keep non-equivalent contracts in separate groups; never compare OI or volume without multiplier/currency normalization.

### P2 — The workflow should be task-led

Recommended information architecture:
1. Discover: asset class, venue, underlying, expiry, search and watchlist.
2. Compare: option chain, market quality, IV surface, skew and term structure.
3. Analyze: Greeks, scenario and payoff, margin and max loss.
4. Replay: historical data and execution-aware backtest.
5. Journal: paper decisions, evidence and outcome review.
6. Data health: provider status, timestamps, missing fields, units and contract lifecycle.

The current navigation already has most analysis components. The main change is to group them around the trader's task and make asset/venue selection explicit.

## Suggested implementation order

1. Canonical asset-class and instrument metadata types plus CSV schema.
2. Asset-class/venue/underlying selector and symbol search.
3. Contract-spec drawer and per-field data provenance.
4. Mobile option-chain cards and responsive Greeks details.
5. Provider health/freshness and venue-comparison model.
6. Model routing for spot, futures, equity, FX and commodity options.
7. Only then add more live data providers, after compliance and licensing checks.

## Implementation status update — 24 November 2026

The first navigation/metadata foundation was merged in PR #5 and published:
- Added AssetClass taxonomy for crypto, equity, index, rates, FX, energy, metals, agriculture, other and unknown.
- Added venue, underlying kind, quote/settlement asset, contract multiplier, exercise style, settlement style and expiry timezone fields to the quote/CSV model.
- Added CSV parsing and template columns for those fields.
- Added Asset Class and multi-Venue selectors; available choices derive from loaded contracts. The current Demo dataset still contains only Crypto, Metals and Energy, so Equity/Index/Rates/FX/Agriculture appear only when supplied by an imported dataset or a future permitted provider.
- Verified the deployed DOM exposes the Asset Class selector; GitHub Pages smoke test and live market-data proxy check passed.

Published-site representative Lighthouse median from 3 runs after PR #5:
- Performance 99/100; Accessibility 91/100; Best Practices 96/100; SEO 100/100.
- FCP 756 ms; LCP 756 ms; TBT 137 ms; CLS 0.000; transfer size 104 KiB.

Remaining high-priority work:
- The chain, journal and Greeks tables still have wide minimum widths and horizontal scrolling on narrow phones; mobile cards/detail sheet are not implemented.
- No underlying symbol search/watchlist yet; class and venue filtering is only the first navigation layer.
- Contract metadata is stored, but the new Black-76/generalized Black-Scholes pricing library is a separate foundation and is not yet wired into the app's quote-ingestion, CSV or scenario paths.
- No new traditional-market data provider has been enabled; no all-asset-class live coverage is claimed.
- Screenshot pixels were not inspected in this session; the audit remains source/DOM/CSS-based, with real-device visual/accessibility testing still outstanding.


## تصحيح حالة التنفيذ — 24 نوفمبر 2026

الملاحظات السابقة عن غياب فلاتر Asset Class/Venue كانت صحيحة قبل دمج PR #5، لكنها لم تعد تمثل النسخة الحالية. الكود الحالي يحتوي على فلتر فئة الأصل وفلتر منصة تُشتق خياراتهما من العقود المحملة، واختبار Playwright يؤكد عزل عقود Equity المستوردة حسب المنصة. لا تزال التغطية الحية أضيق من نطاق المنتج.

**المتبقي بعد PR #5 وما بعده:**
- لا يوجد بحث عالمي عن رمز/اسم الأصل أو watchlist.
- لا توجد بطاقة مواصفات كاملة لكل عقد تربط المضاعف/التمرين/التسوية/الرسوم والهامش بمسار التسعير الفعلي.
- لا يزال mobile chain/Greeks يعتمد على جداول عريضة/تمرير أفقي في أجزاء من الواجهة؛ اختبار عدم وجود overflow على مستوى الوثيقة لا يثبت قابلية قراءة كل جدول.
- مكتبة Black-76 والتسعير المعتمد على مواصفات العقد موجودة كأساس مستقل، لكن يلزم تتبع أماكن استدعاء كل نموذج من ingestion إلى السيناريوهات والتأكد من رفض العقود غير المدعومة.
- لا توجد مقارنة متعددة المنصات للعقود المكافئة ولا أرشفة تاريخية كاملة لسلاسل الخيارات.
- نتائج Lighthouse المنشورة بعد PR #5 هي baseline وليست بديلاً عن اختبار بصري على جهاز Android/iPhone واختبارات قارئ الشاشة واللمس.

**ترتيب التطوير التالي:** (1) توحيد contract spec مع model router في جميع مسارات البيانات، (2) البحث وwatchlist، (3) عرض محمول compact chain + details sheet، (4) health/provenance لكل حقل ومصدر، (5) أرشفة Parquet/replay، (6) مزودات جديدة بعد الترخيص والأهلية فقط.


## إضافة بعد تنفيذ البحث وقائمة المفضلة — 24 نوفمبر 2026

أضيف إلى الواجهة حقل بحث عالمي عن الرمز أو اسم الأصل ضمن العقود المحمّلة، مع اقتراحات `datalist`، واختيار الأصل عند تطابق الرمز/الاسم بالكامل. أضيف زر مفضلة للأصل الحالي وشريط مفضلات. تحفظ المفضلات محلياً في `localStorage` وتبقى بعد إعادة تحميل الصفحة، لكنها لا تتزامن بين الأجهزة أو المتصفحات ولا تتضمن بيانات حساب.

أضيف اختبار Playwright يغطي البحث، إضافة أصل للمفضلة، استمرارها بعد reload، والعودة إلى الأصل بالنقر على المفضلة. لا يزال البحث يقتصر على قائمة العقود الحالية في Demo/CSV/Binance؛ لا يجلب أسواقاً عالمية من تلقاء نفسه.
