## High-priority UX findings

### P0 — Asset selection exists, but the loaded instrument universe is still narrow

Evidence: the current app has an `AssetClass` taxonomy, filters for asset class and venue, underlying selection, global symbol/name search, and a local watchlist. Choices are derived from loaded quotes rather than a complete exchange-wide instrument directory.

Impact: the navigation structure can handle multiple classes and venues, but it cannot discover contracts that no enabled provider supplies. A multi-asset UI is not evidence of global market coverage.

Change:
- Keep the existing cascading Asset Class → Venue → Underlying → Expiry flow and search/watchlist.
- Add licensed, provider-backed instrument directories only after coverage, eligibility and redistribution rights are verified.
- Show coverage counts and an explicit unavailable state for asset classes/venues with no loaded instruments.

### P0 — Contract metadata exists, but model coverage and validation are incomplete

Evidence: `OptionQuote` now carries asset class, venue, underlying kind, forward, quote/settlement assets, multiplier, exercise/settlement style, expiry timezone, filters and fee fields. The pricing router supports explicitly European contracts using Black–Scholes with carry or Black-76; American/Bermudan exercise and incomplete specifications are rejected rather than approximated silently. The selected-contract panel still exposes only a subset of the normalized contract specification.

Impact: metadata presence alone does not guarantee that every ingestion, CSV, replay and scenario path applies the correct multiplier, settlement, fees and model. Unsupported contract mechanics must never inherit a European model by default.

Change:
- Validate a canonical instrument-spec object at every ingestion boundary and retain source values plus normalization provenance.
- Route only explicitly supported mechanics to Black–Scholes with carry or Black-76; keep American/Bermudan products unsupported until a separately validated model is implemented.
- Display multiplier, exercise, settlement, quote/settlement currency, expiry timezone, tick/lot rules, fee and model provenance in the contract detail panel.

### P1 — Greeks and journal tables still require horizontal scrolling on phones

Evidence: PR #76 adds selectable option-chain cards at widths up to 760px and hides the 680px desktop chain table. The journal table (750px) and Greeks table (780px) remain horizontally scrollable.

Change:
- Done: compact mobile option-chain cards retain Strike/moneyness, Bid/Ask, IV, Delta, OI, volume and spread; desktop keeps the dense comparison table.
- Remaining: replace the wide Greeks table with responsive metric cards/details and improve the journal table on narrow phones.
- Verify touch-target size, keyboard focus and screen-reader announcements on real iOS/Android devices.

### P1 — Market freshness is not equivalent to streaming freshness

Evidence: Binance data is fetched as a REST snapshot and the UI tracks local receive age. A 60-second local threshold does not establish upstream timestamp freshness for every field.

Change:
- Show separate source timestamp and received-at timestamp per provider/field where available.
- Use clear labels: Live stream, REST snapshot, Historical, Imported CSV, Demo.
- Show quote age and stale status per selected contract.
- Never show a green “live” status solely because the local fetch happened recently.

### P1 — Venue comparison and market quality are not yet first-class

Evidence: the UI displays one data mode and a selected underlying. It does not yet show same-contract cross-venue quote comparison, depth-adjusted execution cost, or provider health.

Change:
- Add venue comparison only for genuinely equivalent contract definitions.
- Compare executable bid/ask, depth at intended notional, spread, fees, slippage and timestamp alignment.
- Keep non-equivalent contracts in separate groups; never compare OI or volume without multiplier/currency normalization.

### P2 — The workflow should be task-led

Recommended information architecture:
1. Discover: asset class, venue, underlying, expiry, search and watchlist.
2. Compare: option chain, market quality, IV surface, skew and term structure.
3. Analyze: Greeks, scenario and payoff, margin and max loss.
4. Replay: historical data and execution-aware backtest.
5. Journal: paper decisions, evidence and outcome review.
6. Data health: provider status, timestamps, missing fields, units and contract lifecycle.

The current navigation already has most analysis components. The main change is to group them around the trader's task and make asset/venue selection explicit.

## Suggested implementation order

1. Canonical asset-class and instrument metadata types plus CSV schema.
2. Asset-class/venue/underlying selector and symbol search.
3. Contract-spec drawer and per-field data provenance.
4. Mobile option-chain cards and responsive Greeks details.
5. Provider health/freshness and venue-comparison model.
6. Model routing for spot, futures, equity, FX and commodity options.
7. Only then add more live data providers, after compliance and licensing checks.

## Implementation status update — 24 November 2026

- FCP 756 ms; LCP 756 ms; TBT 137 ms; CLS 0.000; transfer size 104 KiB.

Remaining high-priority work:
- The option chain now uses compact selectable cards on mobile; the journal and Greeks tables still require horizontal scrolling, and a mobile Greeks detail sheet is not implemented.

- Screenshot pixels were not inspected in this session; the audit remains source/DOM/CSS-based, with real-device visual/accessibility testing still outstanding.


## تصحيح حالة التنفيذ — 24 نوفمبر 2026

الملاحظات السابقة عن غياب فلاتر Asset Class/Venue كانت صحيحة قبل دمج PR #5، لكنها لم تعد تمثل النسخة الحالية. الكود الحالي يحتوي على فلتر فئة الأصل وفلتر منصة تُشتق خياراتهما من العقود المحملة، واختبار Playwright يؤكد عزل عقود Equity المستوردة حسب المنصة. لا تزال التغطية الحية أضيق من نطاق المنتج.

**المتبقي بعد PR #5 وما بعده:**
- البحث عن الرمز/اسم الأصل والمفضلة موجودان محلياً، لكن المفضلة لا تتزامن بين الأجهزة وتبقى محدودة بالعقود المحمّلة.
- بطاقة المواصفات لا تعرض بعد جميع تفاصيل المضاعف/التمرين/التسوية/الرسوم والهامش ومصدر التطبيع.
- سلسلة الخيارات أصبحت بطاقات محمولة؛ ما زال جدول Greeks والدفتر التجريبي يعتمدان على التمرير الأفقي. يلزم اختبار بصري ولمسي على أجهزة فعلية.
- مكتبة Black-76 والتسعير المعتمد على مواصفات العقد موجودة كأساس مستقل، لكن يلزم تتبع أماكن استدعاء كل نموذج من ingestion إلى السيناريوهات والتأكد من رفض العقود غير المدعومة.
- لا توجد مقارنة متعددة المنصات للعقود المكافئة ولا أرشفة تاريخية كاملة لسلاسل الخيارات.
- نتائج Lighthouse المنشورة بعد PR #5 هي baseline وليست بديلاً عن اختبار بصري على جهاز Android/iPhone واختبارات قارئ الشاشة واللمس.

**ترتيب التطوير التالي:** (1) فرض contract-spec validation وmodel routing على مسارات Binance/CSV/replay والسيناريوهات، (2) تحسين Greeks والدفتر التجريبي على الهاتف، (3) إظهار مصدر/عمر/وحدة كل حقل مع صحة المزود، (4) بناء أرشيف تاريخي قابل لإعادة التشغيل، (5) مزودات إضافية بعد إثبات الترخيص والأهلية فقط.


## إضافة بعد تنفيذ البحث وقائمة المفضلة — 24 نوفمبر 2026

أضيف إلى الواجهة حقل بحث عالمي عن الرمز أو اسم الأصل ضمن العقود المحمّلة، مع اقتراحات `datalist`، واختيار الأصل عند تطابق الرمز/الاسم بالكامل. أضيف زر مفضلة للأصل الحالي وشريط مفضلات. تحفظ المفضلات محلياً في `localStorage` وتبقى بعد إعادة تحميل الصفحة، لكنها لا تتزامن بين الأجهزة أو المتصفحات ولا تتضمن بيانات حساب.

أضيف اختبار Playwright يغطي البحث، إضافة أصل للمفضلة، استمرارها بعد reload، والعودة إلى الأصل بالنقر على المفضلة. لا يزال البحث يقتصر على قائمة العقود الحالية في Demo/CSV/Binance؛ لا يجلب أسواقاً عالمية من تلقاء نفسه.

## توسيع النطاق وتصحيح قرار المنصة — 24 نوفمبر 2026

- Binance ليست «كل الخيارات»: Crypto Options API غني ببيانات mark/Greeks/IV/OI والـWebSocket، لكن Stock Options API منفصل ومرجع عقود فقط ولا يقدم quotes/Greeks/IV؛ Commodity Options المنشورة تقتصر حالياً على XAU/XAG وهي retail long-only. التحقق من أهلية Stock Options للسوريين منفصل عن FAQ سوريا العام.
- IBKR available countries لا يسرد سوريا. لا يوجد وسيط تقليدي بديل مؤكد حالياً.
- فلاتر Asset Class/Venue والبحث والمفضلة في الواجهة لا تعني وجود تغطية سوق عالمية؛ قائمة العقود الفعلية هي التي تحدد خيارات البحث. يجب أن تظهر فجوة التغطية بوضوح بدل عرض فئات فارغة وكأنها متصلة.
- ترتيب التطوير التالي: (1) Contract Spec drawer يوضح نوع المنتج والتسوية والمضاعف ومصدر البيانات، (2) model router يميز Black-Scholes/Black-76/American approximation ويرفض المواصفات الناقصة، (3) مصدر بيانات Stock Options مؤخر/EOD منفصل، (4) Parquet archive/replay، (5) NautilusTrader/QuantLib isolated validation، (6) اختبار واجهة mobile compact chain/details sheet.


## بوابة قانونية خاصة بالإقامة السورية — 24 نوفمبر 2026

يجب أن يظهر في الواجهة تنبيه واضح: أهلية الحساب لدى المنصة لا تعني أن التداول مسموح محلياً. صدرت تحذيرات سورية رسمية/منقولة رسمياً بشأن التعامل بالعملات الرقمية والمنصات غير المرخصة. إلى أن يتضح انطباقها على الخيارات الخارجية، لا يقدم Volterra أي مسار تنفيذ حي للمقيم في سوريا؛ القراءة والتحليل وPaper Trading فقط. لا تضع VPN كخيار لتجاوز هذه البوابة.
