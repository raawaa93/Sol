## High-priority UX findings

### P0 — Asset selection exists, but the loaded instrument universe is still narrow

Evidence: the current app has an `AssetClass` taxonomy, filters for asset class and venue, underlying selection, global symbol/name search, and a local watchlist. Choices are derived from loaded quotes rather than a complete exchange-wide instrument directory.

Impact: the navigation structure can handle multiple classes and venues, but it cannot discover contracts that no enabled provider supplies. A multi-asset UI is not evidence of global market coverage.

Change:
- Keep the existing cascading Asset Class → Venue → Underlying → Expiry flow and search/watchlist.
- Add licensed, provider-backed instrument directories only after coverage, eligibility and redistribution rights are verified.
- Show coverage counts and an explicit unavailable state for asset classes/venues with no loaded instruments.

### P0 — Contract metadata exists, but model coverage and validation are incomplete

Evidence: `OptionQuote` now carries asset class, venue, underlying kind, forward, quote/settlement assets, multiplier, exercise/settlement style, expiry timezone, filters and fee fields. The pricing router supports explicitly European contracts using Black–Scholes with carry or Black-76; American/Bermudan exercise and incomplete specifications are rejected rather than approximated silently. The selected-contract panel still exposes only a subset of the normalized contract specification.

Impact: the pricing router is already used in Binance crypto ingestion, metadata-aware CSV ingestion and synthetic Demo generation. Remaining risk is inconsistent semantics at the boundaries: multiplier/unit, settlement asset, fees, unsupported exercise styles, and expiry payoff versus theoretical valuation. Unsupported contract mechanics must never inherit a European model by default.

Change:
- Validate a canonical instrument-spec object at every ingestion boundary and retain source values plus normalization provenance.
- Verify `unit` versus `contractMultiplier` and settlement/quote currency through payoff, Greek, CSV and replay calculations; do not assume similarly named fields are interchangeable.
- Keep American/Bermudan, perpetual and unknown mechanics unsupported until a separately validated model is implemented.
- Display multiplier, exercise, settlement, quote/settlement currency, expiry timezone, tick/lot rules, fees and model provenance in the contract detail panel.

### P1 — Real-device accessibility and touch validation remains

Evidence: PR #76 adds selectable option-chain cards at widths up to 760px; PR #78 adds mobile Greek-sensitivity cards and paper-journal cards, hiding the wide desktop tables at the same breakpoint. Playwright verifies the 390px layout, data visibility, selection, and card-level horizontal overflow.

Change:
- Done: mobile cards cover option-chain quotes, five Greek sensitivities and paper-journal records while desktop retains dense comparison tables.
- Remaining: inspect actual rendered screenshots on iOS/Android, verify 44px touch targets, keyboard focus, screen-reader labels and long-symbol wrapping. Browser automation is not a substitute for real-device accessibility validation.

### P1 — Market freshness is not equivalent to streaming freshness

Evidence: Binance data is fetched as a REST snapshot and the UI tracks local receive age. A 60-second local threshold does not establish upstream timestamp freshness for every field.

Change:
- Show separate source timestamp and received-at timestamp per provider/field where available.
- Use clear labels: Live stream, REST snapshot, Historical, Imported CSV, Demo.
- Show quote age and stale status per selected contract.
- Never show a green “live” status solely because the local fetch happened recently.

### P1 — Venue comparison and market quality are not yet first-class

Evidence: the UI displays one data mode and a selected underlying. It does not yet show same-contract cross-venue quote comparison, depth-adjusted execution cost, or provider health.

Change:
- Add venue comparison only for genuinely equivalent contract definitions.
- Compare executable bid/ask, depth at intended notional, spread, fees, slippage and timestamp alignment.
- Keep non-equivalent contracts in separate groups; never compare OI or volume without multiplier/currency normalization.

### P2 — The workflow should be task-led

Recommended information architecture:
1. Discover: asset class, venue, underlying, expiry, search and watchlist.
2. Compare: option chain, market quality, IV surface, skew and term structure.
3. Analyze: Greeks, scenario and payoff, margin and max loss.
4. Replay: historical data and execution-aware backtest.
5. Journal: paper decisions, evidence and outcome review.
6. Data health: provider status, timestamps, missing fields, units and contract lifecycle.

The current navigation already has most analysis components. The main change is to group them around the trader's task and make asset/venue selection explicit.

## Suggested implementation order

1. Canonical instrument-spec validation and a complete contract-spec detail panel.
2. Audit multiplier, unit, settlement and currency semantics end-to-end across ingestion, payoff, Greeks, CSV and replay.
3. Extend model coverage only for product mechanics supported by verified contract terms and independent test vectors.
4. Distinguish REST snapshots from exchange WebSocket streams and add streaming only with reconnect, sequence-gap and staleness controls.
5. Build licensed historical-chain storage/replay and equivalent-contract venue comparison.
6. Complete real-device accessibility and touch validation.
7. Add further live providers only after regional eligibility, licensing and redistribution rights are verified.

## Model-routing integration audit — 24 November 2026

A source-level trace corrected the earlier statement that the pricing router was not connected to ingestion or CSV:

- `src/lib/binance.ts`: invokes `priceOption` only for recognized crypto option underlyings, using carry yield 0 and labelling the resulting Greeks `ASSUMED`. Binance TradFi/commodity and unknown underlyings remain `OBSERVED_ONLY`; no Black–Scholes fallback is applied to those paths.
- `src/lib/csv.ts`: routes rows through `priceOption`; there is no legacy generic Black–Scholes fallback. Missing IV is solved only for explicit supported mechanics with required inputs. An observed IV can be imported with `OBSERVED_ONLY` when mechanics are unsupported; missing IV without a supported model causes the row to be rejected.
- `src/lib/demo.ts`: uses `priceOption` for synthetic Demo quotes. This is simulation, not live market evidence.
- `src/lib/options.ts`: risk-neutral expiry metrics require `pricingStatus === SUPPORTED`, European exercise, explicit settlement and matching model/underlying mechanics. Greek shock display is gated by model availability.
- `src/lib/options.ts`: the expiry payoff chart uses intrinsic payoff (`getExpiryPnl`), not theoretical option re-pricing. `src/lib/replay.ts` uses timestamped observed Bid/Ask snapshots and does not use model prices.

Remaining validation gaps: verify `unit` versus `contractMultiplier` across all calculation and import paths; confirm quote/settlement currency and fee treatment in every payoff/replay output; validate model outputs against independent reference vectors for each supported product; keep American/Bermudan, perpetual and unknown mechanics blocked until dedicated models and contract terms are verified. This audit is source-based; it does not certify every provider's live product specification.
