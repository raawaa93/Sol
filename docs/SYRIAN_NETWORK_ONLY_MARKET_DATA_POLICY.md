# سياسة مصدر بيانات Binance — شبكة سوريا فقط

**الحالة:** سياسة تشغيل ملزمة للمشروع  
**تاريخ الاعتماد:** 25 نوفمبر 2026  
**النطاق:** بيانات السوق العامة لخيارات Binance داخل هذا المستودع.

## القرار

- يُسمح بطلبات بيانات Binance فقط عندما يبدأها المستخدم من مسار شبكة سوري فعلي سبق التحقق منه (Syriatel / دمشق)، ومن خلال موصل Volterra للقراءة فقط.
- لا يُستخدم GitHub Actions أو أي runner أجنبي لجلب بيانات Binance أو لاختبار endpoints الخاصة بها.
- لا يوجد اتصال REST مباشر بديل من واجهة التطبيق. يجب تمرير كل طلبات REST وعمق دفتر الأوامر عبر عنوان الوسيط المعتمد الذي يحقنه بناء GitHub Pages.
- عند HTTP 451 أو أي رفض من المصدر، يتوقف الجلب ويُعرض الخطأ. لا VPN، لا تدوير IP، لا تثبيت منطقة تنفيذ أجنبية، لا تبديل بلد، ولا fallback إلى مضيف آخر.
- لا يُسمح بتشغيل جامع WebSocket أو عامل أرشفة مستقل لجلب Binance خارج هذا المسار المعتمد. أي تفعيل مستقبلي يحتاج مراجعة هندسية مستقلة وإثبات أن مصدر الاتصال سوري ومسموح، دون التحايل على قيود المنصة.
- Demo وCSV والاختبارات المحلية ليست مصادر Binance حية، ويجب أن تبقى موسومة بوضوح.

## ما ثبت وما لم يثبت

اختبار 24 نوفمبر 2026 سجل 50/50 استجابة HTTP 200 من طلبات صُنفت شبكياً SY / Damascus / 3G Syriatel، عبر موصل Supabase Edge v10. نُفذت الوظيفة في `eu-west-2` (لندن). هذا يثبت نجاح تلك الدفعة من مسار عميل Syriatel، ولا يثبت وجود خادم مستضاف داخل سوريا أو ضمان الاستمرارية أو أهلية حساب Binance أو صلاحية التداول.

لا توجد في المستودع بيانات موثقة عن عنوان خادم سوري مخصص أو مزود استضافة سوري. لذلك لا يجوز وصف Supabase Edge بأنه «سيرفر سوري». التوجيه الإقليمي إلى `eu-west-2` أو أي منطقة أجنبية ليس بديلاً عن إثبات مصدر الاتصال السوري، وتمت إزالة تثبيت المنطقة من مسار الجلب.

## ضوابط تمنع تكرار الخطأ

1. حذف سير عمل GitHub Actions الذي كان يستطلع Binance كل 15 دقيقة؛ لا يُعاد إنشاؤه.
2. تعطيل طلبات REST المباشرة في `src/lib/binance.ts`؛ غياب عنوان الوسيط يؤدي إلى رفض محلي قبل أي اتصال شبكي.
3. إزالة fallback المباشر من واجهة التطبيق؛ رفض الوسيط لا يطلق طلباً بديلاً.
4. اختبار E2E يثبت أن HTTP 451 لا يطلق أي طلب إلى `eapi.binance.com` مباشرة.
5. اختبار CI للموقع يجب أن يفحص صفحات وملفات النشر فقط، ولا يرسل طلبات إلى Binance.

## قيد إنفاذ جغرافي مهم

المسار الحالي لا يملك بوابة جغرافية موثوقة تمنع كل استدعاء خارجي غير سوري على مستوى الخادم. تقييد CORS إلى نطاق الموقع لا يساوي مصادقة أو تحقق بلد، كما أن ترويسات البلد التي يرسلها العميل قابلة للتزوير. لا نضيف حظراً جغرافياً شكلياً يعتمد على ترويسة يختارها العميل. إنفاذ بلد المصدر تقنياً يتطلب بوابة موثوقة تتحقق من عنوان العميل عبر بيانات بلد موثوقة قبل تمرير الطلب؛ هذه البوابة غير متاحة حالياً ضمن موارد المشروع المتصلة.

إلى أن تتوفر بوابة موثوقة، يظل المسار السوري هو المسار التشغيلي الوحيد المعتمد، وتُمنع جميع مسارات الجلب البديلة في التطبيق وCI. لا يُدّعى أن الحظر الجغرافي الكامل قد نُفّذ.

## التحقق بعد كل تغيير

- `npm test`
- `npm run build`
- `npm run test:e2e`
- فحص أن workflow لا يحتوي Binance polling أو استدعاء upstream.
- اختبار من شبكة Syriatel الفعلية ومراجعة سجلات Cloudflare/Supabase مع التأكد من تصنيف المصدر SY، ونجاح Binance upstream HTTP 200.
- إذا لم يثبت بلد المصدر أو فشل upstream، لا تُستخدم البيانات الحية ولا تُعرض كأنها متاحة.
